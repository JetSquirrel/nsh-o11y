Time-series charts that stay fast at 10 million points.

Observability charts for Native Shell: a TSX TimeSeriesChart with an opt-in Rust backend, and logs, trace waterfalls, flame graphs and latency heatmaps beside it. Live metrics, zoom, synced panels, thresholds and deploy markers, drawn on NSH's native canvas on iOS, Android, desktop and the web.

Built for dashboards that never stop

A frame costs what the plot's width does, not what the data does. Everything else an O11y panel needs comes with it.

Level of detail, exactly

Each series keeps a min/max pyramid. A frame takes the first, min, max and last of each pixel column (M4), so a spike one sample wide in ten million is still drawn.

Opt-in Rust backend

Register it and samples live in Rust: they cross once, when appended, and each frame one SVG path per series comes back. Past NSH's 256 MB JS heap, to hundreds of millions of samples.

Live data

append one sample or a batch. maxPoints keeps a window by shifting the pyramid, not rebuilding it; window shows the last N minutes and follows.

Made for O11y

Units (reqps, ms, bytes, percent…), calendar-aware time axes, SLO thresholds, deploy and incident annotations, gaps, steps and fills.

Synced panels

createChartSync() shares the crosshair and the zoom across every chart on the page. Two canvases per chart: moving the pointer never redraws the data.

Accessible, headless, exportable

Keyboard navigation, a screen-reader label with every value at the cursor, PNG export. The store, engine and renderer are plain TypeScript you can run without the view.

Logs, traces and profiles, too

The other signals on the same canvases and the same theme, linked to each other: a log line opens its trace, a heatmap cell opens a request in it. The demo's tabs show each one.

LogView

Level toggles with counts, search, a stacked volume histogram to drag a time range on, and a virtualized list. Live frames don't rescan: 13 ms at 50,000 lines in NSH's interpreter.

TraceWaterfall

Spans as a tree of bars by service, errors outlined, the critical path underlined, span events marked. An overview to brush a range on; only the rows in view are drawn, at any trace size.

FlameGraph

Zoom to a frame, search, walk it from the keyboard. Pass a baseline for a diff (red grew, blue shrank), or open a function in a SandwichView, between its callers and callees.

Heatmap

A latency distribution over time with percentile lines: a slow minority shows as its own band where p99 just rises. Exemplars link cells to traces; hours of data sum into columns that fit the screen.

A few lines of TSX

Make a store, append to it, hand it to the chart.

  • Any data source. A store from createTimeSeries, or plain arrays: { x, ys }. NaN is a gap.
  • Reactive controller. range(), following() and cursor() are signals; setRange, zoom, back, toImage.
  • Rust when you need it. One call to setNativeBackend; every store after it lives in Rust, and apps without Rust keep working.
  • Follows your theme. Colors come from NSH theme tokens, light and dark, or override any of them.
  • Draws the same everywhere. Rust and TypeScript trace identical paths; the tests check it.
import { mount } from "nsh";
import { TimeSeriesChart, createChartSync,
         createTimeSeries } from "nsh-o11y";

const latency = createTimeSeries({ series: 3, maxPoints: 100_000 });
setInterval(() =>
  latency.append(Date.now(), [p50(), p95(), p99()]), 1000);

function App() {
  const sync = createChartSync();
  return (
    <TimeSeriesChart
      title="Latency"
      data={latency}
      series={[{ label: "p50" }, { label: "p95" }, { label: "p99" }]}
      unit="ms"
      window={15 * 60_000}            // the last 15 min, live
      thresholds={[{ value: 250, label: "SLO" }]}
      annotations={[{ time: deployedAt, label: "deploy v2.14" }]}
      sync={sync}
      style={{ flex: 1 }}
    />
  );
}

mount(App);

Faster than the charts you know

The same data, the same 1000 × 300 plot, each library set up as its docs recommend for big series, each in a fresh headless Edge. nsh-o11y runs its own TypeScript engine on the same page, so the comparison is like for like. JavaScript time per frame; lower is better.

Full-view frame

The whole series on screen, recomputed, as a pan, a resize or new data needs.

Plotly (scattergl) draws on the GPU, which isn't in JavaScript time: once its upload is done (14 s at 10M), a frame mostly moves a camera: 18.7, 18 and 14.5 ms.

Inside NSH: TypeScript or Rust

NSH runs TSX on QuickJS, an interpreter, everywhere but the web. The Rust store does the per-sample work natively and brings an NSH app to browser speed or better. Measured with nsh test perf.
